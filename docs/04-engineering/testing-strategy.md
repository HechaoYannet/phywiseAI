# 测试策略

## 单元与协议测试

- contracts 类型形状。
- domain helper 行为。
- API schema 序列化与反序列化。
- `python -m pytest apps/api/tests -q` 作为 Python 基线检查。

## 集成测试

- 空白工作台创建与保存。
- 板内导入到 source 节点生成。
- `analyze-source` 到 suggestions 生成。
- `accept/reject` 到 `WorkspaceDocument` patch 应用。
- Tutor 回合生成。
- 仿真重建。
- `pnpm typecheck` 与 `pnpm build:web` 作为 Node 侧基线检查。

## 端到端测试

- 学生完成一次空白建题/导题到受力分析检查流程。
- 教师查看一次过程回放。

## 白板 UI 验证基线

当前前端白板仍以浏览器级手工/半自动验收为主。涉及画布坐标、选区、移动端布局或浏览器快捷键的改动，至少覆盖：

- 桌面视口创建空白工作台，插入受力模板后，所有节点不得被顶栏、工具栏或 AI 侧栏遮挡，也不得被视口裁切。
- 移动视口创建空白工作台，插入受力模板后，节点必须落在顶栏、底部工具栏和收起 AI 入口之间的安全区域。
- 导入题目后再插入受力模板时，模板节点不得压到题干/摘要/AI 建议生成块上，受力图内的 body、surface、force、label 子元素必须仍可点选。
- 导入流程至少覆盖文本、图片和 PDF；图片/PDF 预览节点必须加载成功，空文本或未选文件提交必须在前端给出错误提示且不得请求后端。
- `Ctrl+S` 等浏览器常用快捷键不得被白板全局监听器拦截；复制操作走工具栏菜单，不再绑定浏览器书签冲突快捷键。文本输入框内的 `Ctrl+Z`、`Backspace`、`Delete` 也不得触发画布撤销或删除。
- 如本机可用 Microsoft Edge，应至少用 Edge 会话复测首屏、模板插入和上述快捷键探针。
- 至少抽样验证一个选中对象的缩放或旋转手柄，确认 DOM 几何实际变化且无运行时错误。
- 锁定受力图节点后，即使子元素仍处于选中态，也不得显示或响应子元素缩放/旋转手柄。
- 本地可按本节清单复跑首屏、模板几何和锁定手柄回归；`Ctrl+S` 仍建议保留在 Edge 手工探针里复测。

## 关键验收

- 低置信度题目进入确认模式。
- Tutor 不泄露原始推理链。
- 同一 `WorkspaceDocument` 可被不同客户端消费。
